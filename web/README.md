# Tonmeister — Web 版

デスクトップ版（`desktop/InstRecorder`）を、そのままブラウザへ移したもの。
画面の作りと言葉づかいは同じ。同じ2モード（「録る」「重ねる」）で動く。

デスクトップ版が Windows のミキサーを避けるために ASIO / WASAPI 排他を最優先にしているのと同じ理由で、
Web 版は **ブラウザの加工を明示的に全部切る**ことを最優先にしている。

## 開き方

**公開版（https）** — <https://aiwotukauakaunt-gif.github.io/tonmeister/>
GitHub Pages に `web/` がそのまま載る（`.github/workflows/pages.yml`。main に push すると数十秒で更新）。
マイクは https か localhost でしか使えないので、スマホや別の PC から使うにはこちら。ホーム画面に置けば PWA として開く。

**手元で**

```bash
node web/serve.js
```

`http://localhost:8787` を開く。

`file://` で直接開くとマイクを使えない（安全な文脈ではないため）。付属のサーバは Node だけで動き、依存パッケージは無い。

## ブラウザの加工を切る、ということ

ブラウザは既定でマイク入力に手を入れる。入ったままだと、録れるのは「実際に鳴っている音」ではない。

| 加工 | 既定 | このアプリ |
|---|---|---|
| エコー消し（echoCancellation） | 入 | **切** |
| ノイズ抑制（noiseSuppression） | 入 | **切** |
| 自動で音量調整（autoGainControl） | 入 | **切** |

切ったつもりでも、ブラウザが要求を無視することがある。だから

- 状態ピルに**実際にどうなったか**（`getSettings()` の結果）を1行で出す
- 「音のチェック → ブラウザが加工していないか調べる」で、**鳴らして測って**確かめる
  （1kHz を鳴らしている間と、静かにしたあとのレベルを比べる。60 dB 以上落ちるなら加工が働いている）

デスクトップ版で内蔵マイク＋WASAPI 共有モードのときに見つけた「静かな間だけ入力を潰す処理」は、
ブラウザでも同じ形で起きる。同じ検査をそのまま移してある。

**再標本化はそもそも通さない。** Chrome / Edge では **生フレーム取得**（`MediaStreamTrackProcessor`）で
マイクのトラックから直接 `AudioData` を読む。AudioContext を通らないので、ブラウザが受け取っているレート・チャンネル数のまま届き、
録音のレートもそれになる。状態ピルには `生取得` と出る。
それが無いブラウザでは AudioContext 経由に戻り、機器のレートと違えば `⚠ 再標本化 44.1k→48.0k` と出る
（「詳しい設定 → 音の細かさ」を機器と同じ値にすれば消える）。

**Chrome はそのままだとモノラルに畳む。** 何も言わなければ 2ch を頼む（「詳しい設定 → チャンネル数」）。
**「声だけ抽出」（`voiceIsolation`）も切る。** 楽器録音では致命的。

**Windows 側の上限はアプリからは変えられない。** ブラウザは Windows のミキサーを通るので、
「サウンド設定 → 録音 → 既定の形式」が 16bit だと 24bit の機材でも 16bit しか届かない。
届いた値の刻みを見て **「16bit の刻みに乗っている」と見抜く**（音のチェック → 静かにして測る → 届いているビット数）。

## できること

デスクトップ版と同じもの。

**録音**
- 32bit float WAV または 24bit PCM WAV で保存
- 入力レベルメーター（1.5 秒ピークホールド）。「ちょうどいい」帯（−18〜−8 dBTP。float32 で録るなら熱くする意味は無く、機材の手前で歪むのが唯一の損失なので余裕を取る）を常時表示
- **True Peak** — メーターと「割れるか」の判定は、サンプルの間も含めた最大値（4倍オーバーサンプル・ITU-R BS.1770 の考え方）で見る。
  サンプル値だけだと「割れていない」と嘘をつく
- **平らな頭の検出** — 0 dBFS に届かないまま波の頭が平らになった（＝プリアンプや ADC の手前で歪んだ）音を数え、
  録り終わりに「機材側で歪んでいます」と言う
- 録音中は **OPFS のファイルへ 0.5 秒ごとに同期追記**（`storage-worker.js`）。GB 級でも一定の速さで書け、
  途中でタブを閉じても書けたところまでは残り、次に開いたときに拾える。OPFS が無いブラウザでは IndexedDB に 2 秒ごと
- 取りこぼした回数を隠さず画面に出す
- **クロックのずれ（ドリフト）** — 送り側（マイク）と鳴らす側（AudioContext）の進み方を比べて ppm で出す。
  10 分で 5ms を超えるなら「録る機器と鳴らす機器を同じに」と言う（詳しい設定 → ズレ合わせ）
- **押す前の音も残す（プリロール）** — 録音していない間も直近の音（既定 5 秒、最大 20 秒）を輪っかで持ち、
  押した瞬間にその前を先頭に付ける。重ねて録るとき（頭を捨てて前の音と揃えるとき）には付けない
- **落ちた音を本当に数える** — `AudioData.timestamp` と届いたフレーム数の累計を比べ、ゆれの幅を超えて 5 枚続いたずれだけを
  「落ちた」とみなす。落ちたぶんは無音で埋めて時間の長さを保ち（重ね録りがずれない）、回数と場所を録音中バーと波形の赤い印で出す。
  録音していないときに落ちても状態で知らせる（PC が重い／機器のバッファが小さいサイン）
- **自分のフォルダにも書く** — File System Access API で選んだフォルダに、録りながら 20 秒ごとの部分ファイル（それぞれ正しい WAV）を閉じていき、
  止めたら1本にまとめる。ブラウザが落ちても部分ファイルが残り、次に開いたとき繋いで拾う（`disk-writer.js`）
- **眠らせない・閉じさせない** — 録音中は `wakeLock` で画面を起こしておき、タブが裏に回ってもタイトルで「録音中」を示し、閉じようとすると止める
- **長時間** — 受け皿が 1 GB（32bit float・ステレオで約 93 分）に達したら、ブロックの境目で次の受け皿へ切り替える。サンプルは1つも落ちない。
  止めると「続き」のトラックがその位置から並ぶ（`startSeconds`）。書き出しの WAV は 4 GB を超えると RF64 で書き、大きな音も 64 MB ずつ刻んで Blob にする
- **多入力の機材** — 届いている入力のうち「どれを録るか」（すべて／1-2／3-4／1つだけ）と、「1本に／別トラックに／2ch を保険に」を選べる
- **保険トラック** — ch2 を ch1 の予備（機材側で −12 dB など）として録ると、本線が割れたところ（0.985 以上）だけを保険で差し替えた録りを自動で足す。
  倍率は割れていない区間から最小二乗で実測（自己検証：+12.0 dB を +12.0 と出す）。継ぎ目は 10 ms の等パワークロスフェード。元の 2ch の録りも残る
- **ズレ合わせを自動で** — 音の入り口を開いたとき（と機器を変えたとき）に一度だけ往復を測る。切れる

**録音の質（経路の外で起きる劣化を見つける）**
- **経路の格** — 開いた瞬間に 1.5 秒測って、状態ピルの下に ◎／○／△ と1行で出す（`quality.js`）。
  生取得か・再標本化か・ブラウザの加工・16bit で届いていないか・暗騒音・ハム・超音波・落ちた音・クロックのずれ。
  音が鳴っていた間は暗騒音を判定せず、静かになったら測り直す。ビット数は音が出たときに確定する。「詳しく」で理由と手当てが出る
- **試し弾きで音量を決める** — 「いちばん強く鳴らして」6 秒の True Peak と平頭検出から「あと 4 dB 上げられます／3 dB 下げてください／機材側で歪んでいます」。
  目標は −12 dBTP。**帯は −18〜−8 dBTP** に広げた。float32 で録るなら熱くする意味は無く、機材の手前で歪むのが唯一の質の損失なので、余裕を取る方が質が上がる
- **クロックのずれを再生側で相殺** — 測った ppm を、重ね録りのときだけ既存トラックの `playbackRate` に掛ける（1 ± ppm/10⁶）。
  録音経路には触らない。機器の組ごとに覚えるので、次に開いてすぐの重ね録りでも使える。マイクとヘッドホンが別機器のときの「後半でずれる」が消える
- **超音波の雑音** — 20 kHz〜ナイキストの帯を 1〜10 kHz の床と比べ、+12 dB 以上なら「スイッチング電源・ディスプレイ・USB を離す」と言う。耳に聞こえないが録音には入り、後処理で折り返す
- **24bit 保存に TPDF ディザ** — 24bit の刻みに乗っていない値（float32 で録った・ミックスした）にだけ足す。乗っている値には触らないので「24bit で録った音は完全に無劣化」は保たれる（自己検証 ⑪）
- **経路の自己検証** — 生フレーム取得の道と AudioContext の道で **同時に** 2 秒録って比べる（音のチェック → 経路を検証する）。
  周期的な楽音でも迷わないよう、相関の高い候補それぞれで揃えたあとの残差を出し最小を採る。この開発機では **1 サンプルも違わず一致**（時間差 16.67 ms）＝ブラウザは途中でゲインもリサンプルも掛けていない

**録音の証明と、アプリの外を測る**
- **BWF（Broadcast Wave）** — 書き出す WAV に `bext` チャンク。録った日時、`TimeReference`（続きのトラックは開始位置のサンプル数 → DAW に置くと正しい位置に並ぶ）、
  `CodingHistory` に経路の証拠（`path=raw;arrived=24bit;processing=off;verify=identical;floor=-78.0dBFS;gaps=0;drift=-5ppm`）。
  テイクごとに **録音証明**（`provenance`：入り口・道・加工・届いたビット数・経路検証・暗騒音・落ち・クロック）を残し、`_録音証明.txt` として書き出す
- **スイープ測定**（`sweep.js`）— 対数スイープ（Farina 法）を鳴らして録り、逆畳み込みで IR を得る。スイープ自身の素通し特性を引くので、逆フィルタのうねりは残らない（自己検証：素通しで 0.00〜+0.00 dB）
  - **ループバック**：ケーブルで出力→入力。往復の周波数特性（1/6 oct、1 kHz 基準）、1 kHz の **THD+N・SNR → 実効ビット**（雑音は倍音の裾を除いたビンの中央値から出すので、窓の漏れで頭打ちしない）。Windows の隠れた EQ（APO）はここで露見する
  - **部屋とマイク**：スピーカー→マイク。帯域ごとの **RT60**（125 Hz〜8 kHz、シュレーダー積分 T20）、**初期反射**（何 ms・何 dB → 面までの距離 cm と櫛形の谷の周波数）、**フラッターエコー**（包絡線の自己相関）、直接音／響きの比
- **マイク位置の録り比べ** — A/B/C を 5 秒ずつ録り、ピーク・RMS・低域の膨らみ（近接効果）・明るさ・ハム・L/R の距離差を表で並べ、1/3 オクターブの分布を重ねる。音は残さない
- **マイクの較正ファイル** — 測定用マイクの「周波数 dB」テキストを読み、周波数分布からマイクの色を引く。仕上げ層には「マイクの色を戻す」（逆特性の直線位相 FIR・4096 タップ）。
  素には触らない。FIR の遅れは書き出しで先頭を切って揃え、生で聞き比べるときは素側に同じ遅れを置く（値は変えない）
- **クリック検出** — 落ちた穴とは別の、1 サンプルの飛び（USB・ドライバ）。前 1 ms の差分の実効値の 12 倍を超え、次のサンプルで戻るものを数え、波形に印
- **ステレオペアの幾何** — L/R の時間差を **cm** に、レベル差を dB に。「R のマイクが音源から 17.2 cm 遠い／L が 2.0 dB 大きい」

**多重録音（オーバーダブ）**
- テイク管理（同じトラックに何本でも録り、後から選び直せる。古い録りは消えない）
- トラックごとの音量・ミュート・ソロ・リネーム
- レイテンシ補正（UI 上は「ズレ合わせ」）。1kHz の整合フィルタ＋3回の一致判定
- 再生中は**出力のレベル**を表示（聞こえないのがアプリ側か機器側かを切り分けるため）
- 録り終わりに一言（「小さすぎます（−35.8 dBFS）」など）
- 録音一覧、取り消し（外したトラックを1つだけ戻せる）

**波形編集**
- レーンでのドラッグ選択、「波形を見て直す」での拡大（横 ×60 まで／縦は「自動」つき）
- 選択範囲の切り出し
- 部分録り直し（パンチイン）— 助走2秒つき、前後 5ms の等パワークロスフェード
- どちらも元の音には触らず、新しいテイクとして増える
- 波形は**音の大きさ（dB）の目盛り**（−60 dBFS で中心、0 dBFS で枠いっぱい）

**素と仕上げ（盛る／盛らない）**

画面も音も、**「素」と「仕上げ」の2層**に分けてある。楽器の練習では、残響や整えは音程の甘さや立ち上がりの粗さを隠すので、
素を消してはいけない。

```
素（録る）    加工ゼロで float32 WAV に保存。常に残る。どの操作でも変わらない
見る          メーター・True Peak・ノイズフロア・届いたビット数・L/R の時間差 …… 読むだけ
仕上げ（盛る）風音カット・ハム除去・ゲート・ホールの響き・音量そろえ。再生と書き出しのときだけ通る
```

- 仕上げが1つでも入ると、録音名とトラック名に **「盛り」の札**が出る
- 再生は「聞く：素／仕上げ」で切り替える。既定は素。**再生中でも瞬時に切り替わる**（素の経路と仕上げの経路を常に両方作り、最後のゲインで入れ替える。`finish.js`）
- **B を押している間だけ素**。盛ってごまかしていないかを、演奏者がその場で確かめる
- 仕上げの内容は `session.json` に持ち、素の WAV には一切書き込まない。切れば1サンプルも違わず元に戻る（自己検証 ⑧・⑨）

**盛りの段階ダイヤル** — つまみ1つ。細かく触ると「自分で決める」になる

| 段 | 名前 | 中身 |
|---|---|---|
| 0 | 素 | 何もしない |
| 1 | 整える | 風音（30 Hz 以下）カット・ハム除去・音量そろえ −1 dBTP。音色は変えない |
| 2 | 部屋 | 整える ＋ 小さな部屋の響き（0.7 秒・量 25%） |
| 3 | ホール | 整える ＋ 室内楽ホールの響き（1.3 秒・量 45%）。ホール・長さ・量・間は変えられる |

**ホールの響き** — デスクトップ版の `HallImpulse` をそのまま移植（`reverb.js`）
- 小さな部屋 / 室内楽ホール / 大ホール / 石の教会。寸法から作る。前半は鏡像法（3次まで）、後半は3帯域の雑音で高い音ほど早く減らす。吸音率はザビーンの式から逆算
- **直接音には触らない。** 響きだけを足す。量 0% は素と不一致 0 サンプル、量 100% でも響きが届く前は素と一致（自己検証 ⑨）
- トラックごとの「響きの量」（0〜200%、全体の量に対する倍率）
- 書き出しは響きの尾のぶん自動で長くなる
- 実測 T30 と指定値のずれ 3.6〜5.4%、左右の相関 0.005、ConvolverNode と素直な畳み込みの最大誤差 2.2×10⁻⁸

**盛り度を「測る」** — 宣言ではなく実測
素のミックスと仕上げのミックスを両方作って比べる。
- 音量（最小二乗で合わせた倍率）／音の変化（音量を合わせたあとに残る差。素に対する dB）／尾（素が終わったあと −60 dB までの秒数）／静かな部分の変化（下位 2 割のブロック）
- 無・小・中・大 の4段。「小」は音の変化 −30 dB 未満かつ尾 0.2 秒未満＝耳ではほぼ分からない
- 書き出すと `_仕上げ.txt` に「何をどれだけ盛ったか」と盛り度を添える。聞く人にも分かる形で残す

**ハムの周波数を自動で合わせる** — 「音のチェック → 録った音を調べる」でハム（暗騒音より +12 dB）が見つかったら、そのトラックのハム除去を 50 / 60 Hz の測った方に合わせておく

**書き出し**
- **必ず「素」を出す**（`<名前>_素.wav`）。盛りが入っていれば「仕上げ」も並べて出す（`<名前>_仕上げ.wav`）。仕上げだけ、は選べない
- 32bit float / 24bit WAV。書き出す前に **True Peak** で「音が割れるか」を先に見せる
- **セッションを丸ごと書き出す** — `session.json` と WAV がフォルダに並ぶ。
  デスクトップ版が読める形なので、そのまま持ち運べる
  （対応ブラウザではフォルダを選んで直接書き込み、それ以外は1つずつダウンロード）

**音のチェック**
- ブラウザが加工していないかの検査
- 暗騒音の測定：ノイズフロア、実効ビット深度、直流オフセット、クリップ
- **届いているビット数** — 値の刻みから 16bit / 24bit / float を見抜く（Windows の「既定の形式」が 16bit のままかどうか）
- **L/R の時間差と極性** — 2本のマイクで録るとき、距離差（ms）と逆相を相互相関で出す。合わせると低音が痩せる前に気づく
- 電源ハム（50/60Hz とその倍音）の検出
- 1/3オクターブの周波数分布グラフ
- 録音済みトラックの解析
- 測定値から「次に何をすべきか」の所見

**運用**
- **読み込む** — 丸ごと書き出したフォルダ（session.json ＋ WAV）と、デスクトップ版のセッションフォルダをそのまま読む（録音一覧 → 読み込む、または画面へ落とす）。
  名前・トラック・テイク・仕上げが戻り、BWF の `TimeReference` から開始位置も戻る。WAV は素のまま置き場所へ（変換なし）
- **WAV を足す** — 1本の WAV を新しいトラックに（「重ねる」の WAV を足す、または落とす）。レートが違えば変換せずに断る
- **あと何分録れるか** — 置き場所の空きから、いまのレート・チャンネル数で録れる時間を「録る」画面に出す。10 分を切ると知らせる
- **自動バックアップ** — フォルダを選んであれば、保存のたびに（5 秒まとめて）`session.json` の写しを書く
- **整理** — 録音一覧に容量・全体の合計・空きを出し、チェックしてまとめて消せる
- **元に戻す** — Ctrl+Z / Ctrl+Y（Ctrl+Shift+Z）。名前・録りの選び直し・音量・消音・単独・仕上げ・外す・切り出し・録り直し・録音・持ち込み。
  セッションの JSON を控えて戻すだけで、音は消さない（50 段）
- **英語** — 右上の EN で切り替え（keyboard と同じ `T()` 方式。画面の文はすべて、動きながら出る文は主なものを英語に）

**少なく見せる**
- 上の帯は **書き出す** と **≡ メニュー** だけ。録音一覧・読み込み・音のチェック・測る・比べる・詳しい設定・English はメニューの中
- 「録る」は状態ピル（格の印 ◎○△ を含む）・録音ボタン・メーター・判定・試し弾き。ほかは **…** の中。経路の格の詳しい箱は「手当てが要る」ときだけ自動で開く
- 「重ねる」の仕上げカードは**段階ダイヤルだけ**。盛り度・素で聞くボタン・聞く（素／仕上げ）・ズレ合わせ未測定の札は、必要になったときだけ現れる
- 詳しい設定は **入り口・細かさ・残し方・押す前の音** の4つだけ見せ、残りは「くわしい設定 ▸」に畳む。音のチェックは「静かにして測る」1つ＋「ほかの測り方 ▸」
- 文字は一段大きく（15px）、行間を広く

**スマホ・PWA**
- `manifest.json` と `sw.js` でホーム画面に置けて、オフラインでも開く（ネットワーク優先 → 失敗したらキャッシュ。keyboard と同じ型）
- 820px 以下では縦に積む：レーンの下にインスペクタ、トランスポートは折り返し、窓は全画面、押すものは 40px 以上
- iOS Safari など操作なしでは音を開けない環境では「タップして始める」を出す。生取得・wakeLock・フォルダが無い環境では、最初に一度「この環境では〜」と正直に言う

**FLAC 書き出し**（`flac.js`、依存なし）
- 4096 サンプルのブロック、FIXED 予測 0〜4 次から残差最小を選び、Rice 符号（分割 0〜6 次）。定数ブロックは CONSTANT、大きくなるなら VERBATIM
- 24bit の値を1つも変えない。自己検証はブラウザの復号器で読み戻して **不一致 0**（同じレートの OfflineAudioContext なので再標本化は入らない）
- 書き出しダイアログの3枚目「FLAC で残す（24bit 可逆）」。容量はおよそ 0.65〜0.75

**keyboard の中で（本格録音）**
- 練習ツール keyboard（<https://aiwotukauakaunt-gif.github.io/keyboard/>）の「🎚️ 本格録音」として、同一オリジンの iframe（`record/index.html?host=keyboard`）で開く。`js/host.js` が親の `window.KB` と話す。単体で開いたときは何もしない
- **keyboard の音も録る** — 鍵盤・メトロノーム・伴奏ループ・ドローン（親のアプリ音バス）を、マイクの録りと同じ合図で**別のトラック**「keyboard の音」に録る（`js/side.js`）。マイクの経路には触らない。モノラル・1 GB で打ち止め
- 揃え方：生フレーム取得のときは、マイクと同じ Worker で受け、`AudioData.timestamp`（同じ時計）でマイクの開始・停止と同じ時刻に切る。2 つの経路（Worker と AudioContext）の遅れの違いに左右されず、**標本の単位で揃う**（合成音の検証で差 0）。AudioContext 経由のときは同じ AudioContext の worklet で受ける
- 置く位置：本線の「押す前の音」ぶん後ろへ。1本目はさらにズレ合わせで測った往復の遅れぶん後ろへ（奏者が聞いて合わせたクリックの位置に演奏が揃う）。重ね録りは本線の頭を往復ぶん捨ててあるので、そのまま
- 言語は親に追従（`<html lang>` を見る）。録音を始めると親の練習記録の計測が始まる。自分の Service Worker は登録しない（親のが `record/` も持つ）
- 写し方：`python web/tools/sync_keyboard.py` が `web/` → `Keyboard/record/` を同期し、keyboard の `sw.js` の資源一覧と CACHE 名（中身のハッシュ）を書き換える。開発の本拠はこちら

## 置き場所

デスクトップ版はフォルダ1つ＝セッション1つだったが、ブラウザにフォルダは無いので **IndexedDB** に同じ形で持つ。
録音中の受け皿だけは **OPFS**（Origin Private File System）に「録音1本＝ファイル1つ」で同期追記する。

| 入れ物 | 中身 |
|---|---|
| `sessions` | `session.json` にあたるもの（素／仕上げの選択も含む） |
| `audio` | WAV そのもの（Blob）。書き出しはこれをそのまま渡す |
| OPFS `tonmeister/rec/` | 録音中の受け皿。0.5 秒ごとに追記（`storage-worker.js`） |
| `chunks` | OPFS が無いブラウザでの受け皿。約2秒ごとにここへ落ちる |
| `settings` | 機器・細かさ・チャンネル数・生フレーム取得・ズレ合わせ・起動のしかた |

持ち出すときは「録音一覧 →（帯の）このセッションを丸ごと書き出す」。

## 音質のための設計方針

デスクトップ版と同じ考え方を、ブラウザでできる範囲で当てている。

| 方針 | ブラウザでの当て方 |
|---|---|
| OS/ブラウザの加工を通さない | `echoCancellation` / `noiseSuppression` / `autoGainControl` を `false` で要求し、実際の値を画面に出す |
| 信号経路にゲイン・フィルタ・リサンプルを入れない | 生フレーム取得ならトラックから直接 `AudioData` を読む。AudioContext を通らないので再標本化が起きない。無ければ `MediaStreamAudioSourceNode` → AudioWorklet へ直行 |
| 既定を 32bit float 保存に | 届くのは元から float32。そのまま WAV にする |
| オーディオスレッドでファイル I/O をしない | 取り込みは `postMessage` で渡すだけ。保存は専用 Worker が OPFS へ同期追記（デスクトップ版の「専用スレッドでファイル I/O」） |
| 取りこぼしを隠さず表示 | 保存に失敗した回数を録音中バーに出す。クロックのずれも ppm で出す |
| 割れは True Peak で見る | サンプル値の 1.0 だけでなく、サンプルの間の最大値と、0.98 で平らになった頭も数える |
| 仕上げは再生経路にだけ挟む | 風音カット・ノッチ・ゲート・響き・音量そろえは再生とミックスダウンの両方に同じ配線（`finish.js`）で入れる。素の WAV には触らない。切れば不一致 0 |
| 盛りは隠さない | 「盛り」の札、盛り度の実測、`_仕上げ.txt` の覚え書き、B で瞬時に素 |

## デスクトップ版との違い

ブラウザの仕組み上、どうしても移せないものと、まだ移していないもの。

- **ASIO / WASAPI 排他は使えない。** ブラウザにその口が無い。
  だから「加工を切る」ことと「切れたかを測る」ことに寄せている
- **機器の生のフォーマットは選べない。** 「〜192 kHz / 24bit・32bit float を列挙」の代わりに、
  希望のレートを機器に頼み、実際に届いた値を出す。ビット深度は Windows の「既定の形式」で決まる（届いた刻みで見抜ける）
- FLAC は自前のエンコーダで書く（デスクトップ版は CUETools）
- **長時間はメモリに縛られる。** 録音そのものは 1 GB ごとに受け皿を切り替えて落とさないが、
  止めたあとの取り込み・再生は各部分をメモリに載せるので、数時間の録りはデスクトップ版のほうが確実
- **同時多入力録音**は未対応（デスクトップ版でも未対応）
- レイテンシはブラウザを1枚はさむぶん、デスクトップ版より大きくなる。
  ダイレクトモニタリングは、この開発機では実用にならない

## 検証用の合成音

マイクが使えない環境（ブラウザの埋め込みペインなど）で画面と流れを確かめるために、

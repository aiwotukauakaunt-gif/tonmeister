# Tonmeister — 楽器のための録音機

「実際に鳴っている音にできるだけ寄せる」ことを最優先にした録音アプリ。
Windows デスクトップ版 → Web 版 → スマホ版 の順に作る。

- **Windows デスクトップ版** … このページ。`app\Tonmeister.exe`
- **Web 版** … `web/`（[web/README.md](web/README.md)）。公開版 <https://aiwotukauakaunt-gif.github.io/tonmeister/>、手元では `node web/serve.js`。
  生フレーム取得（再標本化ゼロ）・True Peak・OPFS への同期追記・「素／仕上げ」の2層（段階ダイヤル・ホールの響き・盛り度の実測・B で瞬時に素）。keyboard への統合はこちらが元になる

## 起動

デスクトップの **「Tonmeister」ショートカット** をダブルクリック。
実体は `app\Tonmeister.exe`（単体ファイル・.NET 7 ランタイム必要）。

録音の保存先は従来どおり `%USERPROFILE%\Music\録音\` のまま。
名前を変えても、これまでに録った音はそのまま開ける。

開発中のビルドを動かす場合:

```bash
cd desktop/InstRecorder && dotnet run
```

## できること

**録音**
- ASIO / WASAPI 排他 / WASAPI 共有 を選べる
- デバイスが**実際に受け付けるフォーマットだけ**を列挙（〜192 kHz / 24bit・32bit float）
- 32bit float WAV または 24bit PCM WAV で保存
- 入力レベルメーター（1.5 秒ピークホールド、クリップ検出）。
  「ちょうどいい」帯（−18〜−8 dBTP）を常時表示し、外れたら何をすればよいかを一言で出す
- 「いま何につながっているか」を状態ピルに1行で表示（共有モードに落ちていれば「詳しい設定」で分かる）
- **長時間録音**：4GB を超えると自動で次のファイルに切り替える。切り替えはバッファの境目で行うのでサンプルは1つも落ちない。再生時は繋げて1本として扱う
- **BWF（Broadcast Wave）** — 録る WAV に `bext` チャンク（録った日時・`TimeReference`（分割した断片には開始位置）・`CodingHistory` に入力の経路）。Web 版から逆輸入
- **True Peak と平らな頭** — メーターはサンプルの間も含めた最大（4 倍補間）で動き、0 dBFS に届かないまま頭が平らになった波（プリアンプの歪み）も「割れ」として扱う。「ちょうどいい」帯は **−18〜−8 dBTP**
- **届いているビット数・超音波** — 音のチェックの所見に「16bit の刻みに乗っている」「20 kHz より上の雑音」が出る

**多重録音（オーバーダブ）**
- 既存トラックをヘッドホンで聴きながら重ね録り
- **テイク管理**：同じトラックに何本でも録り、後から選び直せる。録り直し中は前のテイクが再生から自動的に外れる
- トラックごとの音量・ミュート・ソロ・リネーム
- **レイテンシ補正**（UI 上は「ズレ合わせ」。自動測定）
- 書き出し（用途で選ぶ2枚のカード。書き出す前にピークを調べて「音が割れるか」を先に見せる）
- **再生中は出力のレベルを表示**。「音は出ています（−12.3）」と出るので、
  聞こえないときにアプリ側の問題か、機器の音量の問題かを切り分けられる
- **録り終わりに一言**。止めた直後に「小さすぎます（−35.8 dBFS）」などを画面上部に出す。
  メーターは録っている最中しか見ないので、気づかないまま小さい録りを重ねないため
- **録音一覧** — 名前・トラック数・長さ・日時で並べて選ぶ
- **取り消し** — 外したトラックは、報せの帯の「元に戻す」で1つだけ戻せる
- セッション＝フォルダ1つ。`session.json` と WAV だけなので、フォルダごとコピーすれば持ち運べる

**ダイレクトモニタリング**
- 自分の音をヘッドホンに返す（音量調整つき）
- 録音される信号とは完全に別経路。モニターで何をしても記録内容は変わらない
- 遅延が育たないよう、溜まりすぎたバッファは古い方を捨てる

**波形編集**（レーンでのドラッグ、または「波形を見て直す」）
- 波形を見ながらドラッグで範囲選択、時間軸と縦方向のズーム
- **選択範囲の切り出し** — 長時間録音から良いところだけを取り出す
- **部分録り直し（パンチイン）** — 選択位置から助走2秒つきで録り直し、前後を 5ms のクロスフェードでつなぐ
- どちらも**元の WAV には触らず**、新しいテイクとして追加される
- 波形の縦倍率「自動」で、暗騒音しかない録音でも波形が見える

**後処理（非破壊）**
- **電源ハム除去** — 50/60Hz とその倍音だけを細く削る。検証では **32.7 dB 減衰、1kHz の楽音への影響 0.0 dB**
- **ノイズゲート** — 無音部だけ静かにする。検証では **無音部 42.5 dB 減衰、演奏部 0.0 dB 変化**
- 設定は再生と書き出しのときだけ通る。切れば即座に元の音に戻る

**ホールの響き（非破壊）**
- 録音まるごとに**鳴らす場所**を1つ選ぶ。小さな部屋 / 室内楽ホール / 大ホール / 石の教会
- 実在のホールを録った**インパルス応答（IR）の WAV** も読み込める
- 内蔵ホールは寸法から作る。前半の反射は**鏡像法**（壁を鏡に見立てて音源を映す）で、
  どの壁からいつ返るかを距離そのままに置く。後半は3帯域に分けた雑音で、高い音ほど早く減らす。
  壁の吸音率は「響きの長さ」からザビーンの式で逆算するので、つまみを動かすと反射の強さも一緒に変わる
- **直接音には触らない。** 元の信号はそのまま出し、響きだけを足す。
  「響きの量 0%」は元の音と**1サンプルも違わない**
- つまみは3つ。響きの長さ（0.2〜6.0秒）・響きの量（0〜100%）・直接音から響きまでの間（25〜150ms）
- 書き出しは響きの尾のぶん自動で長くなる（途中で切らない）

**書き出し**
- ミックスダウン（32bit float / 24bit WAV）
- **FLAC**（24bit 可逆圧縮）— 検証で **不一致サンプル 0 個**、容量は WAV の約 69%

**壊れにくさ**
- 録音中は約2秒ごとにディスクへ書き出す
- 起動時に壊れた WAV ヘッダを自動修復（前回異常終了しても録れた音は残る）
- 未処理の例外は `Music\録音\errors.log` に記録し、アプリは動作を継続する
- セッションは20秒ごとに自動保存
- 選んだ機器・音の細かさ・保存形式・ズレ合わせは `Music\録音\settings.json` に覚える。
  次に開いたときは同じ設定から始まる（機器が見つからなければ既定の選び方に戻る）。
  ただし**鳴らす機器だけは、自分で名指ししない限り覚えない**。
  覚えてしまうと、ヘッドホンを挿しても前の機器へ出し続けることになるため

**キーボード操作**

| キー | 動作 |
|---|---|
| Space | 「録る」では録音開始／「重ねる」では再生。録音・再生中は停止 |
| R | 録音 |
| Esc | 停止 |
| Ctrl+S | 保存 |
| Ctrl+M | 書き出す |
| Ctrl+N | 新しく始める |

**音のチェック（旧・音質診断）**
- **Windows が加工していないかの検査** — 1kHz を鳴らしている間と、静かにしたあとの入力レベルを比べる。60 dB 以上落ちるなら、静かな間だけ入力を潰す処理が働いている（＝録れているのは「実際に鳴っている音」ではない）
- 暗騒音の測定：ノイズフロア、実効ビット深度、直流オフセット、クリップ
- **電源ハム（50/60Hz とその倍音）の検出**
- 1/3オクターブの周波数分布グラフ
- 録音済みトラックの解析
- 測定値から「次に何をすべきか」の所見を出す

保存先: `%USERPROFILE%\Music\録音\<セッション名>\`

## 音質のための設計方針

| 方針 | 理由 |
|---|---|
| ASIO / WASAPI 排他を最優先 | Windows のミキサー（自動リサンプル・APO・音声補正）を通らず、ADC の出力がそのまま届く |
| 信号経路にゲイン・フィルタ・リサンプルを一切入れない | 「実際の音」を変えないため。音量調整は録音後にやる |
| 既定を 32bit float 保存に | 24bit までの入力を完全に無劣化で保持でき、0 dBFS を超えても後から下げれば救える |
| オーディオスレッドでファイル I/O をしない | 書き込み待ちでバッファを落とさないため。専用スレッドへキュー渡し |
| 取りこぼしを隠さず表示 | 無音で埋めて誤魔化さず、件数を画面に出す |
| ASIO では録音と再生を同じドライバインスタンスで扱う | ASIO は1インスタンスしか開けない。かつクロックが共有され、重ね録りでズレが蓄積しない |
| 再生を始めるとき出力デバイスを作り直す | WASAPI 出力は数十msのバッファを抱える。作り直さないと「再生が始まった瞬間」がレイテンシ測定時とズレて、重ね録りの頭が合わなくなる |
| ホールの響きは録音経路に入れない | 響きは「足すもの」であって「録るもの」ではない。録音経路は無加工のまま、再生と書き出しでだけ通す。だからいつでも切って元に戻せるし、重ね録りのときも録られるのは生の音だけ |
| 響きは直接音を通さず、別に作って足す | 乾いた音に手を入れると「切れば元通り」が成り立たなくなる。足すだけにしておけば、量 0 で元の音と完全に一致することを検証できる |

無劣化であることは自己テストで検証済み:
24bit PCM → float32 → 24bit PCM の往復で **不一致バイト 0**、float32 は 1.0 超も保持。

ホールの響きも自己テストで検証済み（`Tonmeister.exe --rtest`）:

| 見たもの | 結果 |
|---|---|
| 分割 FFT 畳み込み ↔ 素直な時間領域の畳み込み | 最大誤差 **7.3×10⁻⁸**（信号の最大値比） |
| 響きの量 0% のときの出力 | 元の音と **不一致サンプル 0 個** |
| 響きの量 100%、響きが届く前（先頭30ms） | 元の音と **不一致サンプル 0 個**（直接音は無加工） |
| 内蔵ホールの実測 T30 と指定値 | ずれ **3.7〜4.4%**（0.7 / 1.3 / 2.0 / 3.4 秒） |
| 響きの左右の相関 | **0.01〜0.18**（1.0 なら真ん中で団子になる） |
| 響きの量 100% のときの 響き/直接音 | **0.71**（白色雑音）／量つまみに比例 |
| プリディレイ 25 / 30 / 80ms の実測 | **25.2 / 30.2 / 80.2 ms** |
| 処理の速さ（3.4秒の響き・ステレオ） | 実時間の **18倍速** |

## 画面の構成

画面は **「録る」「重ねる」の2モード**に分かれ、アプリが自動で切り替える。

| | 出るとき | 見えるもの |
|---|---|---|
| **録る** | トラック 0 本のとき | 状態ピル1行・大きな録音ボタン（外周が入力レベル）・音量メーターと一言の判定 |
| **録音中** | 録音を始めた瞬間 | 経過時間・走る波形・止めるボタンだけ。上端が録音中バーに差し替わる |
| **重ねる** | トラック 1 本以上のとき | トランスポート帯・波形レーン・右のインスペクタ |

専門用語（デバイス／API／サンプルレート／ビット深度／レイテンシ）は
**「詳しい設定」1枚に隔離**してあり、ふだんの録音では見えない。
やさしい言葉を主に、原語は小さく副えている（検索できなくならないため）。

1本目が録れると「重ねる」タブのバッジが光るが、**画面は勝手に切り替わらない**。

上部の録音名はクリックで書き換えられる（フォルダ名は変えない。
録音中のファイルを掴んだままフォルダを動かすと、録れた音を失いかねないため）。

### レーンの波形について

波形は **音の大きさ（dB）の目盛り**で描いている（−60 dBFS で中心、0 dBFS で枠いっぱい）。

素の振幅のまま描くと、−36 dBFS で録れた音は 62px の枠の 1.6%（1px 未満）にしかならず、
線1本にしか見えない。かといってトラックごとに倍率を変えると、
トラック同士の大きさを目で比べられなくなる。dB の目盛りなら両方成り立つ。

一度読んだ波形は覚えておき、タブを行き来しても読み直さない。

### 見た目

黒地に金の3色だけで意味を分けている。

| 色 | 意味 |
|---|---|
| **金** | 正しい・選ばれている・良好 |
| **深紅** | 録音・危険 |
| **象牙** | 文字 |

警告は赤銅、波形の選択範囲は藍。光る効果は使わず、余白と細い罫で区切る。

## 使い方

### 1本目を録る

1. 起動すると自動でマイクにつながり、メーターが動き出す
   （つながらないときは状態ピルの「変える」→「詳しい設定」で選ぶ）
2. 楽器をいちばん強く鳴らして、メーターが**金の帯（−18〜−8 dBTP）**に収まるよう機材側で調整。
   帯から外れていれば、メーターの下に何をすればよいかが出る
3. 「録音する」（Space でも可）→「■ 録音をやめる」（Esc / Space）

### 重ね録りする

1. **ヘッドホンを着ける**（スピーカーだと再生音がマイクに回り込んで二重に混ざる）
2. 「重ねる」タブ →「ズレ合わせ 未測定」を押して測る
3. 「録る場所」が「新しいトラックに録る」になっていることを確認して録音ボタン
4. 全部録れたら「書き出す」

### 同じパートを録り直す

「録る場所」を「〈トラック名〉に録り足す」にして録る。
そのトラックは録音中の再生から自動的に外れるので、前の録りが耳に返ってこない。
録り終わるとレーンの下に「1回目・2回目…」の丸ボタンが並ぶので、聴き比べて選ぶ。
**古い録りは消えない**。

### 一部だけ録り直す・切り出す

レーンの波形をドラッグして範囲を選ぶと、その行の下段が
「ここだけ録り直す」「選んだところを切り出す」に変わる。
どちらも元の録音は書き換えず、新しい録りとして増える。
細かく見たいときは、右のインスペクタの「波形を見て直す」から拡大できる。

### ホールの響きをつける

「重ねる」画面の右、**「鳴らす場所」**の札で切り替える。トラックごとではなく**録音まるごと**にかかる。
ホールは場所であって、楽器ごとに別の場所にいることはないため。

1. 「ホールの響きを足す」を入れる
2. ホールを選ぶ。迷ったら **室内楽ホール**（独奏・室内楽なら大ホールは長すぎることが多い）
3. **響きの量**を上げていって、楽器の輪郭がぼやける手前で止める。25〜35% あたりが目安

| つまみ | 何が変わるか |
|---|---|
| 響きの長さ | 残響時間（RT60）。長いほど広く、遠くに聞こえる |
| 響きの量 | 直接音に対する響きの大きさ。100% で直接音と同じくらい |
| 直接音から響きまでの間 | プリディレイ。長いほど壁が遠い＝広い場所に聞こえる。楽器の輪郭も保たれる |

**実在のホールで鳴らす。** 「読み込んだ響き」を選ぶと、そのホールを録ったインパルス応答（IR）の
WAV を指定できる。IR の先頭に直接音が入っていれば取り除く（直接音は元の録音がそのまま担うため、
残すと二重になる）。10秒を超えるぶんは切り捨てる。

**録った音は変わらない。** 響きは再生と書き出しのときだけ通る非破壊の処理で、
元の WAV には一切触らない。切ればその場で元に戻る。
重ね録りの最中に録られるのも生の音だけで、響きは記録されない。

書き出しは響きの尾のぶん自動で長くなる。書き出し画面に「約◯分◯秒」として出る。

### レイテンシ補正について

「聴こえた音」に合わせて弾いた演奏は、**出力遅延＋入力遅延**のぶんだけ後ろにズレて記録される。
補正しないと重ねるたびにどんどん遅れていく。このアプリは録音の頭を指定サンプル数だけ捨てて揃える。

**自動測定**は 1kHz のテスト音を鳴らし、それが録音側に返ってくるまでを測る。
物音を誤検出しないよう、(1) 1kHz 成分だけを見る整合フィルタ、(2) 3回測って値が一致したときだけ採用、
の二段構えにしている。一致しなければ数字を返さず「測れなかった」と表示する。

- ヘッドホンで測るときは、片方をマイクに近づける
- 測定できないときは、Windows の音量が下がっていないか確認する
- ASIO はクロックが共有されるので、そもそもズレが小さい
- 測定値は機材構成を変えたら測り直す

参考値（この開発機・WASAPI 共有・内蔵マイク＋内蔵スピーカー）: 往復 **約 165 ms**。

### ダイレクトモニタリングについて

**必ずヘッドホンを使うこと。** スピーカーだとマイク→スピーカー→マイクの輪ができてハウリングする。

WASAPI 共有では往復 165 ms あるため、演奏しながら聴くには遅すぎる。
アコースティック楽器なら生音が直接耳に入るので、そもそもモニターに返す必要は薄い。
ASIO のオーディオI/Fを使う場合や、I/F 側のダイレクトモニター機能を使う場合に意味が出る。

### 音のチェックの読み方

「録る」画面の「音のチェックをする」、または「重ねる」画面の「音のチェック」から開く。
数字より先に**結論と次の一手**が結論カードに出る。数値カードはその裏づけ。

| 項目 | 見方 |
|---|---|
| ノイズフロア（RMS） | 低いほど良い。−85 dBFS 以下なら静か、−55 dBFS より上なら要改善 |
| 実効ビット深度 | その暗騒音の下で実際に使えているビット数。12 bit を切るなら、24bit で録る前にノイズを下げるほうが効く |
| 電源ハム | 暗騒音より +12 dB 以上なら対策の価値あり。電源アダプタ・ディスプレイからマイクを離す、USBポートを変える |
| 直流オフセット | ヘッドルームを無駄に食う。大きければ機材側の設定を疑う |

### 再生しても音が聞こえないとき

音が出ない原因は、ほとんどが**アプリの外**にある。上から順に確かめる。

1. **Windows 側の音量**
   タスクバーのスピーカーを見る。この開発機では **11%** まで下がっていて、
   小さく録れた音がまったく聞こえない状態だった。
   再生を始めたときに消音・20% 未満なら、アプリが一度だけ知らせ、
   トランスポート帯に「音は出ています・機器の音量 11%」と出し続ける。

   **再生中、トランスポート帯の目盛りは出力のレベルを指す。**
   ここが振れていれば音は確かに出ており、原因は機器側にある。
   1.5 秒以上まったく振れなければ「音が出ていません」と出る。

2. **録れている音が小さすぎる**
   目標は最大音で **−18〜−8 dBTP**。これを大きく下回ると、
   Windows 側の音量を上げてもまだ小さい。
   「音のチェック」→「録った音を調べる」で、そのトラックのいちばん大きいところが分かる。

   参考（この開発機で内蔵マイク・共有モードで録ったもの）:

   | | ピーク | RMS |
   |---|---|---|
   | 13秒のトラック | −35.8 dBFS | −59.4 dBFS |
   | ほかのトラック | −47〜−58 dBFS | −59〜−96 dBFS |

   目標より 30 dB 以上低い。内蔵マイク＋共有モードでは
   Windows の音声補正が入力を絞るため（下の「この開発機で分かったこと」を参照）、
   まず**排他モードか ASIO の機器**に替えるのが本筋。

3. **鳴らす機器の選択**
   「詳しい設定」→「重ね録りのとき、前の音を鳴らす機器」。

   既定は **「自動（Windows がいま使っている機器）」**。
   ヘッドホンを挿せば、そのままヘッドホンへ移る。

   機器を名指しで選ぶと、以後そこへ**固定**される。固定したまま
   Windows 側が別の機器に変わると「他のアプリでは鳴るのにこのアプリだけ鳴らない」が起きるので、
   その状態で再生すると、画面の上に
   「音は『スピーカー』へ出しています。Windows がいま使っているのは『ヘッドホン』です」と出し、
   その場で戻せるようにしてある。

4. **トラックが消音・単独になっていないか**
   レーンの「消音」が入っている、または別のトラックだけ「単独」になっていると鳴らない。

エンジンの再生経路そのものは `--mtest` で検証できる。
「再生経路のループバック確認」が OK なら、音は確かに出力へ届いている。

### この開発機で分かったこと（重要）

内蔵マイク＋WASAPI 共有モードでは、**Windows の音声補正が静かな間だけ入力を潰していました**。

| | RMS |
|---|---|
| 入力を開いた直後 | −88.9 dBFS |
| 数秒後 | −133.8 dBFS |
| さらに後 | −149.1 dBFS |
| 1kHz を鳴らす | **−73.6 dBFS**（+75 dB 復帰） |
| 止めて3秒 | −113.5 dBFS（再び低下） |

音を出すと即座に戻り、止めるとまた落ちるので、機材が静かなのではなく**OSが絞っている**と分かります。

この状態では暗騒音の測定値（「−159 dBFS」「実効 25.6 bit」など）は**機材の性能ではありません**。
実在の機材でそんな数値は出ないので、アプリ側でも −120 dBFS を下回ったら
「あり得ない静けさ」として警告するようにしてあります。

対処は「オーディオ拡張を無効にする」か、**排他モード／ASIO が使える機器を用意する**こと。
このアプリが排他モードと ASIO を最優先にしているのは、まさにこれを避けるためです。

### 排他モードが選べないとき

Windows の 設定 → システム → サウンド → デバイスのプロパティ → 詳細設定 で
「アプリケーションによるこのデバイスの排他制御を許可する」を有効にする。
内蔵マイクなど、そもそも排他モードに対応しないデバイスもある（その場合は共有モード）。

## 開発用モード

```bash
dotnet run -- --selftest 2 C:\temp\report.txt
```
変換の無劣化検証・デバイス列挙・対応フォーマット・実録音テスト。

```bash
dotnet run -- --mtest C:\temp\mtest.txt
```
多重録音の通しテスト。重ね録り・レイテンシ補正の削り量・テイク追加と再生からの除外・
長時間録音の自動分割・セッション保存/読込・ミュート/ソロ・ミックスダウン・
モニターのバッファと配線・再生経路のループバック確認・レイテンシ自動測定。

```bash
dotnet run -- --atest C:\temp\atest.txt
```
解析の数値校正テスト。既知の合成信号（正弦波・量子化ノイズ・ハム・クリップ・広帯域ノイズ）を入れて、
ピーク／RMS／実効ビット深度／スペクトル／ハム検出が理論値と合うかを確認する。

```bash
dotnet run -- --etest C:\temp\etest.txt
```
編集と後処理の検証。既知の合成音（440/880/220Hz を1秒ずつ）を使い、頭出し・切り出し・
パンチインの差し替え位置を周波数で確認し、継ぎ目の不連続、波形データの粒度、
ハム除去の減衰量と楽音への影響、ノイズゲートの効き、FLAC の可逆性（1サンプル単位で照合）を測る。

```bash
dotnet run -- --probe C:\temp\probe.txt
```
排他モードでどのフォーマットが通るかを1つずつ試して記録する（デバイス相性の切り分け用）。

## 既知の制約

- WASAPI では録音と再生が別クロックなので、長時間の重ね録りでは末尾に向かって徐々にズレる可能性がある。ASIO なら共有クロックなので起きない
- トラックは全て 0 秒から始まる（途中から録り「始める」のは未対応。途中を録り「直す」パンチインは対応済み）
- FLAC は仕様上 32bit float を扱えないため、24bit で書き出す。24bit で録った音は完全に無劣化だが、32bit float の音は変換が入る（0 dBFS 超は失われる）
- パンチインの継ぎ目は 5ms のクロスフェードで繋ぐため、その区間だけは元の波形と厳密には一致しない
